## 0. 本章主线（先记住这三句）

1. **互联网可以从两个视角看**：nuts and bolts（主机、交换机、链路、网络）和 services（为应用提供通信服务的基础设施）。
2. **数据走网络 = 分组交换 + 分层封装**；每一层加自己的头部，路由器只处理到网络层。
3. **性能由延迟、丢包、吞吐决定**；四个延迟分量、`La/R`、瓶颈链路是计算题的核心。

**本章常见考法**

## 1. 什么是 Internet

### 1.1 “nuts and bolts” 视角 ★

| 组件 | 作用 | 例子 |
|---|---|---|
| **Host / end system** | 运行网络应用 | PC、手机、服务器、IoT |
| **Packet switch** | 转发分组 | 路由器（router）、交换机（switch） |
| **Communication link** | 传输比特 | 光纤、铜缆、无线电、卫星 |
| **Network** | 设备/路由器/链路的集合 | 家庭网、校园网、ISP 网络 |

- 互联网 = **网络的网络（network of networks）**。
- 链路速率 = **带宽/传输速率**（bps）。
- 分组 = 数据块；交换机采用**存储转发**。

### 1.2 “services” 视角

- 互联网是**为应用提供通信服务**的基础设施。
- 提供 **Socket API**：应用把数据交给网络。
- 服务包括：可靠传输、尽力而为交付、安全传输等（由不同协议组合提供）。

### 1.3 协议（protocol）★

> **协议定义**：① 报文格式（format）；② 报文的顺序/时序（order）；③ 发送或收到报文时采取的动作（action）。

- 人类协议：问“几点了？”→ 对方回答；网络协议：TCP 连接请求 → SYN-ACK。
- 三要素可概括为：**语法、语义、时序**。

**为什么需要协议**：双方必须对“怎么表示、谁先说、收到后做什么”达成一致，否则无法通信。

## 2. 网络边缘（network edge）

### 2.1 接入网络（access networks）★

| 类型 | 结构/介质 | 速率/特点 |
|---|---|---|
| **Cable（HFC）** | 同轴电缆 + 光纤到 headend；共享 | 下行 40 Mbps–1.2 Gbps；上行 30–100 Mbps |
| **DSL** | 电话双绞线到 DSLAM/中心局；专用 | 下行 24–52 Mbps；上行 3.5–16 Mbps |
| **Home network** | cable/DSL modem + WiFi AP + 路由器 | WiFi 54/450 Mbps；有线 1 Gbps |
| **Wireless WLAN** | 802.11b/g/n，基站/AP | 11/54/450 Mbps；共享、受干扰 |
| **Cellular** | 4G/5G 基站 | 数十 Mbps（5G 更高）；广覆盖 |
| **Enterprise** | Ethernet 交换机 + 路由器 | 100 Mbps/1/10 Gbps；WiFi AP |
| **Data center** | 高带宽交换机连接大量服务器 | 10s–100s Gbps |

> 课件未展开 FTTH；可作为补充：光纤到户，速率高、损耗低，但部署成本高。

**共享 vs 专用**：

- Cable、WiFi 是**共享**介质，多用户竞争；
- DSL 是到中心局的**专用**线路；
- 企业网通常有线到桌面、WiFi 覆盖。

### 2.2 物理媒体 ★

| 类型 | 说明 |
|---|---|
| **双绞线（UTP）** | 便宜、易布；速率随类别/距离变化 |
| **同轴电缆** | 有线电视/宽带；共享 |
| **光纤** | 高速、低误码、抗电磁干扰、长距离 |
| **无线电** | 无线、移动；受环境/干扰/距离影响 |

- **导引型（guided）**：信号沿固体介质传播。
- **非导引型（unguided）**：信号在自由空间传播。

### 2.3 主机如何发包

- 应用消息被切成 **packets**，长度 `L` bit。
- 链路传输速率 `R` bps。
- **传输延迟**：`L/R`。
- 交换机 **store-and-forward**：必须收完整包、校验后才转发到下一段。

**例**：L=10 Kbit，R=100 Mbps → `L/R = 10^4 / 10^8 = 0.1 ms`（课件例）。

## 3. 网络核心（network core）

### 3.1 转发 vs 路由 ★

| 概念 | 范围 | 做什么 |
|---|---|---|
| **Forwarding（转发）** | 局部、每个包 | 根据转发表把包从输入端口送到输出端口 |
| **Routing（路由）** | 全局、路径 | 运行路由协议，计算从源到目的的路径 |

> 类比：转发是“在路口看路牌选方向”，路由是“提前规划整条路线”。

### 3.2 分组交换（packet switching）★★

- 数据切成分组，独立传输；**统计复用**（按需共享带宽）。
- **存储转发**：收完整包再转发。
- **排队**：到达速率 > 输出速率 → 包在缓冲区排队；缓冲区满 → **丢包**。
- 优点：适合**突发**流量、带宽利用率高、无需呼叫建立。
- 缺点：排队延迟、丢包、需要可靠传输/拥塞控制。

**两段链路的存储转发延迟**（无排队/处理）：

\[
d = \frac{2L}{R}
\]

### 3.3 电路交换（circuit switching）★★

- 建立连接时**预留**端到端资源（带宽/时隙），通话期间独占。
- **FDM**：频分复用，不同频率带；
- **TDM**：时分复用，周期性时隙。
- 优点：有带宽/延迟保证，适合实时语音。
- 缺点：空闲时浪费、呼叫建立慢、资源利用率低。

### 3.4 分组 vs 电路：经典例子 ★★

**场景**：1 Gb/s 链路；每个用户活跃时 100 Mb/s；活跃概率 10%。

- **电路交换**：每条通话预留 100 Mb/s → 最多 **10** 个用户。
- **分组交换**：35 个用户时，同时活跃超过 10 个的概率 **< 0.0004** → 多数时间不拥塞。
- 结论：**突发型数据用分组交换更高效**；但分组交换不提供硬保证，拥塞时延迟/丢包会上升。

> 计算思路：二项分布 `P(X > 10)`，`X ~ B(35, 0.1)`；课件只要求理解结论。

### 3.5 Internet 结构：网络的网络

- 接入 ISP → 区域 ISP → **Tier-1 ISP**；
- **IXP**（Internet Exchange Point）让 ISP 互联；
- **内容提供商网络**（Google、Netflix、Akamai）自建 CDN/骨干，尽量靠近用户；
- 商业关系：transit（付费传输）、peering（对等互联）、multi-homing（多归）。

## 4. 性能：延迟、丢包、吞吐

### 4.1 四种延迟 ★★

\[
d_{\text{nodal}} = d_{\text{proc}} + d_{\text{queue}} + d_{\text{trans}} + d_{\text{prop}}
\]

| 分量 | 公式/决定因素 | 量级 |
|---|---|---|
| **处理延迟** `d_proc` | 检查比特错误、查转发表 | 通常 < µs |
| **排队延迟** `d_queue` | 取决于拥塞程度、`La/R` | 可从 0 到很大 |
| **传输延迟** `d_trans` | `L/R`（包长/链路速率） | 由包长和带宽决定 |
| **传播延迟** `d_prop` | `d/s`（距离/信号速度） | 由物理距离决定 |

- 信号速度 `s ≈ 2×10⁸ m/s`（光纤/铜缆中约 2/3 光速）。
- ⚠ **传输延迟 ≠ 传播延迟**：前者是“把比特推上链路”，后者是“信号在介质中跑”。

**例**：L=1000 bytes=8000 bit，R=100 Mbps，d=2000 km，s=2×10⁸ m/s。
- `d_trans = 8000 / 10⁸ = 80 µs`
- `d_prop = 2×10⁶ / 2×10⁸ = 10 ms`
- 总延迟 ≈ **10.08 ms**（传播占主导）。

### 4.2 流量强度与排队 ★★

\[
\text{traffic intensity} = \frac{La}{R}
\]

- `a`：平均到达速率（包/秒）；`L`：包长（bit）；`R`：链路速率（bps）。
- `La/R ≈ 0`：排队延迟小；
- `La/R → 1`：排队延迟急剧增大；
- `La/R > 1`：到达大于服务能力，队列无限增长（实际会丢包）。

**例**：L=1000 bytes=8000 bit，a=100 包/秒，R=1 Mbps：
`La/R = 8000×100 / 10⁶ = 0.8` → 接近 1，排队延迟会明显。

### 4.3 丢包（loss）

- 路由器缓冲区有限；到达速率持续超过输出速率 → 缓冲区满 → 后续包被丢弃。
- 丢包后可能重传，进一步加重拥塞。
- 表现：应用超时、吞吐下降、延迟抖动。

### 4.4 吞吐（throughput）★★

- 端到端吞吐 = **瓶颈链路**速率：

\[
\text{throughput} = \min(R_s, R_c, \ldots)
\]

- 若 10 条连接公平共享骨干 `R`，每条吞吐 ≈ `min(R_s, R_c, R/10)`。
- 瓶颈通常是接入链路（`R_s` 或 `R_c`），而不是核心骨干。

**例**：服务器上行 2 Mbps、客户端下行 10 Mbps、骨干 100 Mbps → 吞吐 = **2 Mbps**。

### 4.5 traceroute

- 发送 TTL=1,2,3,... 的探测包；路由器返回 ICMP 超时；逐跳测量 RTT。
- 可以看到路径、每跳延迟、丢包/路由变化。

## 5. 分层与协议栈

### 5.1 为什么分层 ★

- 把复杂系统分解为可管理的模块；
- 每层只依赖下层提供的服务，层内实现可独立演化；
- 便于标准化、互操作、教学。

**代价**：头部开销、层间信息隐藏、跨层优化困难。

### 5.2 五层模型 vs OSI 七层 ★★

| Internet 五层 | OSI 七层 | 功能 | PDU |
|---|---|---|---|
| Application | Application / Presentation / Session | 应用语义、表示、会话 | message |
| Transport | Transport | 进程到进程 | segment |
| Network | Network | 主机到主机、路由 | datagram |
| Link | Data Link | 相邻节点、成帧 | frame |
| Physical | Physical | 比特传输 | bit |

- OSI 的 Presentation/Session 在 Internet 中由应用层自行处理。
- 五层是教学/工程常用模型；OSI 是参考模型。

### 5.3 封装（encapsulation）★★

```
应用层：        M
传输层：    [H_t | M]                segment
网络层：  [H_n | H_t | M]            datagram
链路层：[H_l | H_n | H_t | M]        frame
物理层：  比特流
```

- 每层加自己的头部；接收方逐层解封装。
- 路由器处理到网络层；链路层交换机处理到链路层。
- 头部是“层与层之间的契约”：地址、协议号、长度、校验等。

### 5.4 端到端 vs 逐跳

- 传输层：**端到端**（进程到进程），只在两端实现。
- 网络层：逐跳路由，每个路由器都参与。
- 链路层：逐跳（相邻节点）。

## 6. 网络安全与历史（了解）

### 6.1 常见威胁

| 威胁 | 说明 |
|---|---|
| **Malware** | 病毒、蠕虫、木马、僵尸网络 |

## 7. 例题精讲

### 例 1：四种延迟（10 分）

**题**：L=1500 bytes，R=1 Gbps，链路长 3000 km，s=2×10⁸ m/s，处理延迟 10 µs，排队延迟忽略。求节点延迟。

**解**：
- `L = 1500×8 = 12000 bit`
- `d_trans = 12000 / 10⁹ = 12 µs`
- `d_prop = 3×10⁶ / 2×10⁸ = 15 ms`
- `d_proc = 10 µs`
- `d ≈ 10 µs + 12 µs + 15 ms = 15.022 ms`

**得分点**：单位换算（bytes→bits，km→m，ms/µs）；传播延迟占主导。

### 例 2：存储转发（8 分）

**题**：包长 10 Kbit，链路速率 100 Mbps，经过 2 段链路（1 个路由器），忽略处理/排队。求端到端传输延迟。

**解**：
- 每段 `L/R = 10⁴ / 10⁸ = 0.1 ms`
- 存储转发两段：`2L/R = 0.2 ms`

**得分点**：路由器必须收完整包再转发；三段链路则是 `3L/R`。

### 例 3：分组 vs 电路（10 分）

**题**：1 Gb/s 链路，用户活跃时 100 Mb/s，活跃概率 10%。电路交换最多几个用户？分组交换为什么能支持 35 个？

**解**：
- 电路：`1 Gb/s / 100 Mb/s = 10` 个用户（每人预留）。
- 分组：35 个用户，同时活跃数 `X~B(35,0.1)`；`P(X>10) < 0.0004`，即绝大多数时间不超过链路容量。
- 结论：统计复用提高利用率，但拥塞时会有排队/丢包。

### 例 4：吞吐（6 分）

**题**：服务器上行 10 Mbps，客户端下行 100 Mbps，骨干 1 Gbps，10 条连接公平共享骨干。求单条连接吞吐。

**解**：
- 瓶颈 = `min(10 Mbps, 100 Mbps, 1 Gbps/10 = 100 Mbps)` = **10 Mbps**。
- 若骨干只有 50 Mbps，则 `min(10, 100, 5) = 5 Mbps`。

### 例 5：封装（8 分）

**题**：描述应用消息从主机 A 到主机 B 经过一台路由器时的封装/解封装过程。

**解**：
1. A 应用生成 message M；
2. 传输层加 `H_t` → segment；
3. 网络层加 `H_n` → datagram；
4. 链路层加 `H_l` → frame；物理层发送；
5. 路由器收到 frame，解封装到网络层，查转发表，重新封装成下一段 frame；
6. B 逐层解封装，最终把 M 交给应用。

**得分点**：每层头部、路由器只到网络层、B 逐层解封装。

### 例 6：流量强度（6 分）

**题**：包长 1000 bytes，到达率 200 包/秒，链路 10 Mbps。求流量强度，并判断排队情况。

**解**：
- `L = 8000 bit`；`La/R = 8000×200 / 10⁷ = 1.6`。
- `> 1`：到达速率超过服务速率，队列持续增长 → 严重排队/丢包。

## 8. 易错点（考场最易丢分）

| 错误 | 正确 |
|---|---|
| 传输延迟 = 传播延迟 | 传输是 `L/R`（推比特），传播是 `d/s`（信号跑） |
| 带宽越大，传播延迟越小 | 传播延迟只由距离/介质决定，与带宽无关 |
| 吞吐 = 链路带宽 | 吞吐 = 瓶颈链路速率，可能远小于带宽 |
| 分组交换总是优于电路交换 | 突发流量更高效；实时/有保证业务电路交换更合适 |
| 电路交换“没有延迟” | 有传播/传输延迟，只是没有排队/拥塞 |
| 路由器处理到应用层 | 路由器只到网络层；交换机到链路层 |
| 五层 = OSI 七层 | 五层是 Internet 模型；OSI 有表示层/会话层 |
| 分层越多越好 | 分层有头部/性能开销，是权衡 |
| `La/R=1` 时延迟稳定 | `→1` 时排队延迟急剧增大，`>1` 队列无限增长 |
| 协议只定义报文格式 | 还包括顺序/时序和收到后的动作 |

11. 端到端吞吐由什么决定？10 条连接共享骨干时如何计算？

### 答案

1. 主机/端系统、分组交换机（路由器/交换机）、通信链路、网络（网络的网络）。
2. 报文格式、顺序/时序、收到报文后的动作；人类问时间→回答，网络请求→响应。
3. 分组：统计复用、适合突发、可能排队/丢包；电路：预留资源、有保证、空闲浪费。
4. 处理、排队、传输 `L/R`、传播 `d/s`；传输与包长有关，传播与距离/介质有关。
5. 排队延迟急剧增加、缓冲区溢出丢包；到达速率持续超过输出速率。
6. 传输：把比特推上链路，`L/R`；传播：信号在介质中跑，`d/s`。
7. 应用 message、传输 segment、网络 datagram、链路 frame、物理 bit；逐层加头。
8. 路由：全局路径选择（路由协议）；转发：本地把包从输入端口送到输出端口。
9. 分解复杂系统、模块独立演化、标准化；代价是头部开销、层间信息隐藏。
10. FDM 按频率划分频带；TDM 按时间划分时隙；都是预留资源。
11. 瓶颈链路 `min(R_s,R_c,...)`；10 条公平共享骨干 R 时每条 `min(R_s,R_c,R/10)`。
12. 发送 TTL 递增的探测包，路由器返回 ICMP 超时，逐跳测量 RTT。
