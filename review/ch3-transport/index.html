    第 3 章 · 传输层 · 复习资料¶

    对应课件：ch3-8.pdf（Kurose & Ross, Chapter 3 Transport Layer, 8th ed.）

    建议用时：第一遍 120 分钟 + 例题 50 分钟 + 自测 40 分钟

    配套：知识大纲 §4

    本章权重：全课计算/机制题最密集的一章：rdt、GBN/SR、TCP 序号/ACK/RTT、流量控制、拥塞控制。

    0. 本章主线（先记住这三句）¶

    1. 传输层提供进程到进程的逻辑通信；多路复用/解复用靠端口（TCP 还要四元组）。
    2. 可靠传输 = 确认 + 序号 + 定时器 + 重传；流水线（GBN/SR）用窗口提高利用率。
    3. TCP 在可靠传输之上做流量控制（rwnd）和拥塞控制（cwnd）；AIMD + 慢启动是经典，CUBIC/QUIC 是现代演进。

    本章常见考法

    题型 典型问法 备考动作
    计算 stop-and-wait 利用率、TCP 吞吐、RTT 估计 记公式 + 单位
    机制 rdt2.0 缺陷、GBN/SR 窗口、三次握手 画时序/状态
    分析 给丢包/延迟场景，问重传/ACK 按“序号+定时器”推演
    比较 TCP vs UDP、GBN vs SR、流量 vs 拥塞 列表格
    简答 为什么三次握手？AIMD 为什么公平？ 抓关键原因

    1. 传输层服务¶

    1.1 位置与职责 ★¶

    • 网络层：主机到主机；传输层：进程到进程。
    • 发送方：把应用数据切段、加传输层头、交给网络层。
    • 接收方：重组段、按端口交给正确 socket。
    • 传输层只在端系统实现；路由器不处理传输层。

    1.2 多路复用/解复用（mux/demux）★★¶

    复用（发送方）：从多个 socket 收集数据，加头（源/目的端口等），交给网络层。

    解复用（接收方）：根据头部字段，把段交给正确的 socket。

    协议 解复用标识
    UDP <目的 IP, 目的端口>
    TCP <源 IP, 源端口, 目的 IP, 目的端口> 四元组
    • UDP：目的端口相同但源不同 → 交给同一 socket。
    • TCP：四元组唯一标识一个连接；同一端口可以有多个连接。

    2. UDP¶

    2.1 特点 ★¶

    • 无连接：无握手；每个数据报独立。
    • 不可靠：不保证到达、顺序、不重复。
    • 无流控/拥塞控制：发送方按应用节奏发。
    • 开销小、延迟低、头部只有 8 字节。
    • 适合：DNS、DHCP、SNMP、流媒体、游戏、QUIC 底层。

    为什么用 UDP：

    • 应用自己实现可靠性/实时性；
    • 不想被 TCP 的拥塞控制/重传拖慢；
    • 短请求/响应（DNS）建连成本不划算。

    2.2 UDP 头部 ★★¶

    0               16              31
+----------------+---------------+
| 源端口 (16)     | 目的端口 (16)  |
+----------------+---------------+
| 长度 (16)       | 校验和 (16)    |
+----------------+---------------+
| 数据 ...                        |
+---------------------------------+
    • 长度：头部 + 数据（字节），最小 8。
    • 校验和：覆盖 伪头部 + UDP 头部 + 数据；伪头部含源/目的 IP、协议号、UDP 长度。
    • 计算：16-bit 反码求和，再取反；接收方验证（全 1 表示无校验和，IPv4 可选）。

    校验和很弱：16 位，可能漏检；但比没有好。

    3. 可靠数据传输原理（rdt）★★¶

    3.1 接口与假设¶

    rdt_send(data)        // 上层调用
udt_send(packet)      // 交给不可靠信道
rdt_rcv(packet)       // 从信道收到包
deliver_data(data)    // 交给上层

    逐步增加信道假设：可靠 → 比特错误 → 丢包。

    3.2 rdt1.0：可靠信道¶

    • 发送方：收数据 → 打包 → 发送。
    • 接收方：收包 → 提取 → 交付。
    • 无需 ACK、序号、定时器。

    3.3 rdt2.0：有比特错误 ★¶

    • 需要：差错检测（checksum）、ACK/NAK、重传。
    • 发送方发完等 ACK/NAK；收到 NAK 或损坏 → 重传。
    • 致命缺陷：ACK/NAK 本身可能损坏 → 发送方不知道是“成功”还是“失败”，可能重复发送。

    3.4 rdt2.1：处理损坏的 ACK/NAK ★¶

    • 给数据包加 序号 0/1。
    • 发送方：发送当前包，等待对应 ACK；超时/损坏 → 重传。
    • 接收方：用序号判重；重复包丢弃但回 ACK。
    • 状态数翻倍（等待 ACK0 / ACK1）。

    3.5 rdt2.2：无 NAK ★¶

    • 只使用 ACK；ACK 带“期望的下一个序号”。
    • 接收方收到正确包 → 回 ACK（期望序号）；收到重复/失序 → 回上一次的 ACK。
    • 发送方收到重复 ACK → 重传当前包。
    • 效果与 rdt2.1 等价，但减少一种报文。

    3.6 rdt3.0：有丢包 ★★¶

    • 增加定时器：发送后启动；超时未收到 ACK → 重传。
    • 序号 0/1；处理：
    • 数据丢失 → 超时重传；
    • ACK 丢失 → 超时重传（接收方丢重复）；
    • 延迟 ACK → 可能重复，但序号可处理。
    • stop-and-wait：一次只发一个包，等 ACK；简单但利用率极低。

    3.7 stop-and-wait 性能 ★★¶

    U_sender = (L/R) / (RTT + L/R)

    例（课件）：1 Gbps 链路，单向传播 15 ms（RTT=30 ms），8000 bit 包。 - L/R = 8000/10⁹ = 8 µs = 0.008 ms - U = 0.008 / (30 + 0.008) ≈ 0.00027 - 即发送方只有 0.027% 时间在发数据。

    解决：流水线（pipelining）——允许多个未确认包同时在途，利用率提高 N 倍。

    4. 流水线协议：GBN 与 SR¶

    4.1 Go-Back-N（GBN）★★¶

    发送方

    • 窗口 N：最多 N 个连续未确认包。
    • 序号 k-bit；窗口滑动。
    • 累积 ACK：ACK(n) 表示 n 及之前的包都收到。
    • 一个定时器：只为最老的未确认包计时；超时 → 重传该包及窗口中所有后续包。

    接收方

    • 只按序接收；期望 rcv_base。
    • 收到正确序号 → 交付、回 ACK、rcv_base++。
    • 收到失序包 → 丢弃（不缓存），回最后一个正确包的 ACK（可能重复 ACK）。

    特点：接收方简单；丢一个包会重传整个窗口，浪费带宽。

    4.2 Selective Repeat（SR）★★¶

    发送方

    • 窗口 N；每个包单独定时器。
    • 只重传超时的那个包。
    • 收到 ACK → 标记该包已确认；窗口滑动。

    接收方

    • 缓存失序包；对每个正确收到的包单独 ACK。
    • 按序交付；收到缺失包后，把缓存的连续包一起交付。

    窗口约束：

    N ≤ 2^(k-1)
    • k 为序号位数；序号空间 2^k，窗口不能超过一半，否则无法区分“新包”和“旧包的重传”。
    • 例：k=2（序号 0..3），N 最大 2；N=3 会出现接收方把旧包当新包的歧义。

    4.3 GBN vs SR ★★¶

    维度 GBN SR
    接收方缓存 不缓存失序包 缓存失序包
    ACK 累积 ACK 单独 ACK
    重传 整个窗口 只重传丢失
    定时器 一个（最老包） 每个包一个
    窗口 N N ≤ 2^(k-1)
    复杂度 简单 复杂
    适用 错误少/窗口小 错误多/高带宽

    5. TCP¶

    5.1 概述 ★¶

    • 点对点：一个发送方、一个接收方。
    • 可靠、按序：字节流。
    • 全双工：双向数据。
    • 面向连接：握手建立状态。
    • 流量控制：rwnd。
    • 拥塞控制：cwnd。

    5.2 TCP 段结构 ★★¶

    0               16              31
+----------------+---------------+
| 源端口 (16)     | 目的端口 (16)  |
+----------------+---------------+
| 序号 (32)                       |
+---------------------------------+
| 确认号 (32)                     |
+----+-----+-----+----------------+
|首部|保留 |标志 | 窗口 (16)       |
+----+-----+-----+----------------+
| 校验和 (16)     | 紧急指针 (16)   |
+----------------+---------------+
| 选项（可变）                     |
+---------------------------------+
| 数据 ...                        |
    • 最小头部 20 字节（无选项）。
    • 标志：SYN、ACK、FIN、RST、PSH、URG。
    • 序号：字节流编号，不是包编号。
    • 确认号：期望收到的下一个字节序号（累积确认）。

    5.3 序号与 ACK ★★¶

    • 发送方给每个字节编号；段首字节序号放在 Seq。
    • 接收方 ACK = 期望的下一个字节。
    • 例：发送 1000 字节，Seq=1000；接收方正确收到 → ACK=2000。
    • 丢失/失序：接收方重复 ACK 当前期望值；发送方看到 3 个重复 ACK → 快速重传。

    5.4 RTT 估计与超时 ★★¶

    EstimatedRTT = (1-α)·EstimatedRTT + α·SampleRTT        α = 0.125
DevRTT      = (1-β)·DevRTT + β·|SampleRTT - EstimatedRTT|   β = 0.25
TimeoutInterval = EstimatedRTT + 4·DevRTT
    • EstimatedRTT：平滑的 RTT 估计。
    • DevRTT：RTT 偏差（抖动）。
    • 超时 = 估计值 + 安全边际；偏差大 → 超时更长。
    • 超时太长 → 反应慢；太短 → 不必要的重传。

    例：EstimatedRTT=120 ms，DevRTT=10 ms，SampleRTT=100 ms。 - 新 Estimated = 0.875×120 + 0.125×100 = 117.5 ms - 新 Dev = 0.75×10 + 0.25×|100−120| = 12.5 ms - Timeout = 117.5 + 4×12.5 = 167.5 ms

    5.5 TCP 发送方（简化）★¶

    事件：

    1. 应用传数据 → 封装段 → 启动定时器 → 发送。
    2. 超时 → 重传最老的未确认段 → 重启定时器。
    3. 收到 ACK → 更新窗口；若还有未确认数据 → 重启定时器；否则停止。

    5.6 快速重传（fast retransmit）★¶

    • 收到 3 个重复 ACK（同一确认号）→ 认为该段丢失，立即重传，不等超时。
    • 为什么是 3：少量乱序也会产生重复 ACK；3 个是折中，减少误判。

    5.7 TCP 接收方 ACK 生成¶

    事件 动作
    按序收到、之前都已确认 延迟 ACK（最多 500 ms）
    收到失序段 立即发重复 ACK（期望序号）
    收到填补空缺的段 立即 ACK

    5.8 流量控制 ★★¶

    • 目的：防止发送方淹没接收方缓冲区。
    • 接收方在头部 rwnd（receive window） 通告空闲空间。
    • 发送方保证：未确认数据 ≤ rwnd。
    • 与拥塞控制的区别：
    • 流量控制：接收方限制（端到端）。
    • 拥塞控制：网络限制（全局）。

    5.9 连接管理 ★★¶

    三次握手

    客户端 → 服务器：SYN, seq=x
服务器 → 客户端：SYN-ACK, seq=y, ack=x+1
客户端 → 服务器：ACK, ack=y+1
    • 目的：同步双方序号、确认双方收发能力。
    • 为什么三次：防止旧的重复 SYN 到达服务器，导致建立错误连接；两次不够，四次浪费。

    关闭连接

    • 主动关闭方发 FIN；对方 ACK；对方也发 FIN；最后 ACK。
    • 主动关闭方进入 TIME_WAIT，等待 2×MSL，确保最后的 ACK 能到达、旧包消失。

    5.10 重传场景¶

    • ACK 丢失：发送方超时重传；接收方收到重复 → 再 ACK。
    • 数据丢失：超时/3 个重复 ACK → 重传。
    • 延迟 ACK：可能造成“过早超时”，但序号/ACK 可恢复。

    6. 拥塞控制¶

    6.1 拥塞的代价 ★¶

    • 排队延迟增加；
    • 缓冲区溢出 → 丢包；
    • 重传浪费带宽；
    • 拥塞崩溃（吞吐骤降）。

    三种场景：

    1. 一个路由器、有限缓冲：到达速率接近容量 → 排队/丢包。
    2. 多个路由器、重传：丢包导致重传，进一步加重拥塞。
    3. 四发送方、多跳：竞争带宽，吞吐下降。

    6.2 两种方法¶

    方法 谁做 例子
    端到端 端系统根据丢包/延迟推断 TCP
    网络辅助 路由器显式通知 ECN、ATM ABR

    6.3 TCP AIMD ★★¶

    • 加性增（AI）：每个 RTT cwnd += 1 MSS。
    • 乘性减（MD）：丢包时 cwnd = cwnd/2。
    • 锯齿状：探测可用带宽 → 丢包 → 减半 → 再增。
    • 公平性：多条流竞争时，AIMD 会收敛到大致公平。

    6.4 慢启动（slow start）★★¶

    • 初始 cwnd = 1 MSS。
    • 每收到一个 ACK，cwnd += 1 MSS → 每 RTT 翻倍（指数增长）。
    • 到达 ssthresh 后进入拥塞避免（线性增长）。
    • 超时：ssthresh = cwnd/2，cwnd = 1，重新慢启动。
    • 3 个重复 ACK：快速重传 + 快速恢复：
    • ssthresh = cwnd/2
    • cwnd = ssthresh（或 ssthresh+3）
    • 然后线性增长。

    例：初始 cwnd=1，ssthresh=8。 - 慢启动：1→2→4→8（3 个 RTT）。 - 拥塞避免：9→10→11... - 在 cwnd=12 丢包（3 dup ACK）：ssthresh=6，cwnd=6，然后 7,8,...

    6.5 TCP CUBIC ★¶

    • 用三次函数（以时间为自变量）增长窗口：
    • 靠近上一次拥塞点增长慢，远离时增长快；
    • 更适合高带宽、长延迟网络。
    • Linux 默认；比 AIMD 更稳定、恢复更快。

    6.6 延迟型拥塞控制¶

    • 测量 RTT 变化，保持管道“刚好满”而不引起丢包。
    • 代表：TCP Vegas；BBR 用带宽/RTT 估计。
    • 优点：少丢包；缺点：可能与丢包型流不公平。

    6.7 ECN（显式拥塞通知）¶

    • 路由器在 IP 头标记拥塞（而不是丢包）。
    • 接收方通过 TCP ACK 回显；发送方降速。
    • 需要端到端支持。

    6.8 公平性 ★¶

    • 目标：K 条 TCP 流共享瓶颈，每条约 R/K。
    • AIMD 趋于公平。
    • 破坏公平的因素：
    • 不同 RTT（短 RTT 抢得多）；
    • UDP 不降速；
    • 多并行连接；
    • 应用层不公平。

    6.9 TCP 吞吐（补充）¶

    avg throughput ≈ 0.75·W / RTT
    • W 为丢包时的窗口大小；平均窗口约 3/4 W。
    • 丢包率 L 时（Mathis）：throughput ≈ 1.22·MSS / (RTT·√L)。
    • 高带宽长延迟网络需要大窗口；丢包率必须极低。

    7. QUIC（了解）¶

    • 基于 UDP 的应用层协议；HTTP/3 的传输层。
    • 流级多路复用：一个流丢包不影响其他流（避免 TCP HOL）。
    • 0/1-RTT 建连：减少握手延迟。
    • 内置加密（TLS 1.3）。
    • 连接迁移：手机切换 WiFi/蜂窝时保持连接。
    • 用户态实现，便于快速迭代。

    8. 例题精讲¶

    例 1：stop-and-wait 利用率（8 分）¶

    题：1 Gbps 链路，单向传播 15 ms，8000 bit 包。求 stop-and-wait 的发送方利用率。

    解： - L/R = 8000/10⁹ = 8 µs = 0.008 ms - RTT = 30 ms - U = 0.008 / (30 + 0.008) ≈ 0.00027（0.027%） - 结论：需要流水线提高利用率。

    例 2：GBN 重传（10 分）¶

    题：GBN，N=4，序号 0..7。发送 0,1,2,3；ACK0、ACK1 到达；又发 4,5；包 2 丢失。接收方收到 3,4,5 会怎样？发送方何时重传哪些包？

    解： - 接收方期望 2；收到 3,4,5 都失序 → 丢弃（或缓存，取决于实现），重复 ACK1。 - 发送方收到重复 ACK1，但未到 3 个；包 2 定时器超时 → 重传 2,3,4,5（整个窗口）。 - 接收方收到 2 后按序交付 2,3,4,5，回 ACK5。

    例 3：TCP 序号/ACK（8 分）¶

    题：TCP 发送 2000 字节，Seq=5000；接收方正确收到前 1000 字节，后 1000 字节丢失。接收方回什么 ACK？发送方如何反应？

    解： - 接收方收到 5000–5999，期望 6000 → ACK=6000。 - 后续收到 6000–6999 之外的段（如果有）→ 重复 ACK 6000。 - 发送方收到 3 个重复 ACK 6000 → 快速重传 6000 开始的段。

    例 4：RTT 估计（8 分）¶

    题：EstimatedRTT=200 ms，DevRTT=20 ms，SampleRTT=160 ms。求新的 EstimatedRTT、DevRTT、Timeout。

    解： - Estimated = 0.875×200 + 0.125×160 = 175 + 20 = 195 ms - Dev = 0.75×20 + 0.25×|160−195| = 15 + 8.75 = 23.75 ms - Timeout = 195 + 4×23.75 = 290 ms

    例 5：AIMD（10 分）¶

    题：cwnd=1，ssthresh=16。描述慢启动到 cwnd=16，然后在 cwnd=20 时发生 3 个重复 ACK 的过程。

    解： - 慢启动：1→2→4→8→16（4 个 RTT，指数）。 - 拥塞避免：17,18,19,20（每 RTT +1）。 - 3 dup ACK：ssthresh = 20/2 = 10；cwnd = 10（快速恢复），然后 11,12,... 线性增长。 - 若是超时：ssthresh=10，cwnd=1，重新慢启动。

    例 6：TCP 吞吐（6 分）¶

    题：W=64 KB，RTT=100 ms。估算平均吞吐。

    解： - 0.75×64 KB / 0.1 s = 480 KB/s ≈ 3.84 Mbps。 - 若丢包率高，实际更低；高带宽长延迟需要更大 W。

    9. 易错点（考场最易丢分）¶

    错误 正确
    传输层 = 主机到主机 传输层是进程到进程；网络层才是主机到主机
    UDP 没有校验和 UDP 有 16-bit 校验和（IPv4 可选，通常启用）
    rdt2.0 已经可靠 ACK/NAK 可能损坏 → 有致命缺陷
    GBN 接收方缓存失序包 GBN 通常丢弃失序包；SR 才缓存
    SR 窗口可以等于序号空间 N ≤ 2^(k-1)，否则有歧义
    TCP 序号是包编号 是字节流编号
    ACK 表示“已收到这个序号” ACK 表示“期望的下一个字节”
    超时 = 2×RTT 用 EstimatedRTT + 4×DevRTT
    3 个重复 ACK 一定丢包 也可能乱序；3 是折中
    流量控制 = 拥塞控制 rwnd 防接收方溢出；cwnd 防网络过载
    三次握手是为了加密 是为了同步序号、防旧连接
    慢启动一直指数增长 到 ssthresh 后转线性
    AIMD 丢包时窗口减半 乘性减；超时可能降到 1
    TCP 一定公平 RTT/UDP/并行连接会破坏公平

    8. 快速重传的触发条件？为什么是 3 个重复 ACK？
    9. 流量控制和拥塞控制的区别？rwnd 与 cwnd 分别是什么？
    10. TCP 三次握手的过程？为什么需要三次？
    11. AIMD、慢启动、快速恢复的过程？CUBIC 改进什么？
    12. TCP 公平性是什么？哪些因素会破坏公平？
    13. QUIC 相比 TCP 的优势？

    答案¶

    1. 网络层主机到主机，传输层进程到进程；mux/demux 把段交给正确 socket。
    2. 源/目的端口、长度、校验和；伪头部+UDP 段；16 位反码和，保护弱。
    3. ACK/NAK 可能损坏；rdt2.1 加序号，rdt2.2 用 ACK+期望序号。
    4. 定时器超时重传；U=(L/R)/(RTT+L/R)。
    5. GBN 累积 ACK、一个定时器、重传整个窗口、接收方不缓存；SR 单独 ACK、每包定时器、只重传丢失、缓存失序。
    6. 20 字节；Seq 是段首字节编号，ACK 是期望的下一个字节。
    7. 指数加权移动平均；α 平滑 SampleRTT，β 平滑偏差；Timeout=EstimatedRTT+4DevRTT。
    8. 3 个重复 ACK；说明后续包到了但缺失包没到，网络可能只丢了那一个。
    9. 流量控制防接收方溢出（rwnd），拥塞控制防网络过载（cwnd）。
    10. SYN、SYN-ACK、ACK；同步序号、防止旧连接请求。
    11. AI 每 RTT +1 MSS，MD 丢包减半；慢启动指数增长到 ssthresh；快速恢复在 3 个重复 ACK 后；CUBIC 用三次函数。
    12. K 条流共享瓶颈各得约 R/K；不同 RTT、UDP、并行连接会破坏。
    13. UDP 上实现、流级多路复用、0/1-RTT、内置加密、连接迁移。
